HyperShape.Methods — Module
HyperShape.Methods

Optimisation problems and methods. A method is an operator z ↦ z⁺ over the functionals; all methods share one loop (evaluate, differentiate, step, accept or reject, continuation, stopping, checkpoint) and only the step is specific:

  • DensityMethod: density methods; the step is any Optimizer of HyperShape.Optimizers (OC, SiMPL).
  • ReactionDiffusion: reaction–diffusion of a level set (through an interface map) or of a density, with the volume met exactly at every step.

Level-set methods (phase 2) will plug into the same loop.

HyperShape.Methods.AbstractMethod — Type
AbstractMethod

Supertype of the methods (DensityMethod, ReactionDiffusion; level set later). All methods share the loop of solve! (evaluation, acceptance, continuation, augmented Lagrangian, stopping, checkpoint, output); a method only gives its step and what the step sees of the problem, through four functions (public, not exported):

  • stepper(m): the step, an Optimizer (init, step!, reset!, shrink!, memory, restore_memory!, objective_changed!; see HyperShape.Optimizers); the same object at every call (a continuation compares it);
  • build_oracle(m, problem): the oracle the step sees (objective, gradient, constraints, bounds, metric); for now it must be a HyperShape.Methods.FunctionalOracle (internal: its interface may change), built for example with FunctionalOracle(problem, metric);
  • augmented_lagrangian(m): the AugmentedLagrangian of the constraints the step does not treat;
  • check_problem(m, problem): errors when the run starts (default: none).

method_label(m) (default: the name of the type) and metric_label(m) (default: none) go to the banner, with the lines of banner_lines(m, problem) (default: none; a vector of (text, colour)). feasible_start(m) (default true): whether a starting design that violates the native constraint is scaled to meet it before the first step (ReactionDiffusion: false, its step lowers the volume).

HyperShape.Methods.Checkpoint — Type
Checkpoint(; filepath, every)

Writes the state of the optimisation to the folder filepath every every accepted iterations, and also when the optimisation stops or fails: checkpoint.toml (format version 3: iteration, continuation stage, scales of the functionals by name, who treats each constraint and the multipliers and penalties of the augmented Lagrangian by name, the offsets of the linear constraints, the method and the optimiser, sizes and the names of the other files; the discretisation and its number of rebuilds), z_<iteration>.bin (the design, raw Float64), history_<iteration>.csv and, for optimisers that save one, memory_<iteration>.bin (see memory: its numbers and then its vectors, raw Float64). These are the fields of an OptState. The data files are written first and checkpoint.toml last, under a temporary name and then renamed, so they always belong to the same iteration; older files are then deleted. Resume with solve!(…; resume = filepath) (or the result of load_checkpoint).

HyperShape.Methods.Continuation — Type
Continuation(; every, close_early = false, name = object => values, …)

Continuation of parameters in stages: Continuation(β = proj => [1, 2, 4, 8, 16, 32]; every = 40) (with proj a TanhProjection) uses β = 1 in the first stage, 2 in the second, and so on. A stage ends after every iterations, or when the optimiser finds no acceptable step; with close_early = true, also when the StopCriteria are met (by default they only act in the last stage: early stages can look converged on a grey plateau before the topology forms). The optimisation can only stop in the last stage. At each jump the memory of the optimiser is forgotten (reset!), which costs one more forward solve. All value lists have the same length (the number of stages). Supported objects: Parameter (any number of the user: the penalty of the interpolation, a load factor), TanhProjection (β, through set_beta!) and OC (its move limit, through set_move!: Continuation(β = proj => [1, 2, 4, 8, 16], move = oc => [0.2, 0.2, 0.1, 0.05, 0.025]; every = 50), the same oc given to DensityMethod).

HyperShape.Methods.DensityMethod — Type
DensityMethod(optimizer; metric = default_metric(optimizer), lagrangian = AugmentedLagrangian())

Density method (SIMP, RAMP or any interpolation written by the user in the weak forms): the step is optimizer (any Optimizer: OC(…), SiMPL(…)). metric: LumpedMass(dΩ), Euclidean(), a vector of positive weights (one per entry of z: inner(x, y) = Σ mᵢ xᵢ yᵢ), an object of the user with a method metric_weights(m, z) -> Vector (called once at the start of solve! and again after each rebuild of the problem), or a named tuple with one of them per block of z. SiMPL uses it in its step and its optimality measure, and needs it (no default). OC uses it only for the stationarity measure (see StopCriteria); its default is Euclidean(), which makes that measure depend on the mesh.

lagrangian: how the constraints the optimiser does not treat itself are handled, an AugmentedLagrangian (default AugmentedLagrangian(): Bertsekas with a fixed penalty μ = 1, multipliers updated after every accepted iteration, the first constraints the optimiser handles kept native). It is used only when there is such a constraint, or when its native names fewer than the optimiser would take.

HyperShape.Methods.Discretization — Type
Discretization

Supertype of the discretisations given to solve!(…; discretization): they say whether the problem is built again during the run, when, and how. FixedMesh() (the default) never does; HyperShape.Methods.RebuildCheck does it on the same mesh; adaptive meshes come later. The contract (public, not exported):

  • needs_setup(d): whether the problem must have factories (Optimization(model; design_setup, physics_setup));
  • due(d, k, info, history, ctx) -> Bool: after the accepted iteration k (not the last one, nor the iteration a run resumes from), whether to rebuild; history is the live OptHistory (its first history.n entries are filled);
  • rediscretize(d, problem, state::OptState, ctx) -> Optimization: the new problem (for example HyperShape.Methods.rebuild(problem), or rebuild(problem; what = :physics) to keep the design), called with ctx.phase == :setup; solve! checks it (new variables, unless the design is kept, and new functionals; the same blocks and number of values of z, the same frozen cells, the same constraints with the same bounds and kind, the same monitors and output, a continued TanhProjection in the new maps) and continues from state. A change of mesh (another number of values) is not supported yet;
  • discretization_label(d): the line of the banner.

A rebuild costs the calls of the factories, one forward solve and one filter (counted in the summary of the run, not in the rows of the history). An error at a rebuild, or before the first iteration after it, keeps the state of the rebuild (with the memory of the optimiser) in problem.state[] and in the checkpoint.

HyperShape.Methods.DoubleWell — Type
DoubleWell(; W = 0.25, η = 10.0, T = 25.0, cfl = :auto, scheme = :implicit, settle = true, substeps = nothing)

The double-well reaction of ReactionDiffusion (Takezawa, Nishiwaki and Kitamura 2010; Kim et al. 2020, loop 2), given as ReactionDiffusion(; κ, reaction = DoubleWell()) (or τ = κ/ℓ²). The design is a density φ ∈ [lb, ub] (normally bounds = (0.0, 1.0), read through Identity() and an interpolation in the weak forms) that evolves by

∂φ̂/∂t = τ ℓ² Δφ̂ − W w′(φ̂) − 30 w(φ̂) (η C g/m + λ),     w(φ̂) = φ̂² (1 − φ̂)²,   φ̂ = (φ − lb)/(ub − lb),

with C the normalisation of the method (normalize, L2Norm() by default with the well), g/m the sensitivity density and λ the multiplier of the volume, found exactly at every substep (ExactVolume). Both the sensitivity and the multiplier are weighted by 30 w(φ̂), which vanishes at 0 and 1: the reaction only moves the interface and holes are not nucleated, so the start needs one (built with hole_seed(Vφ; bounds = (0.0, 1.0), …)). The well keeps the design close to 0/1 with an interface of width ξ = √(κ / 2W). κ = τ ℓ² is a physical parameter, the same on every mesh: on a coarse mesh the interface is thinner than a cell. With the well κ (or τ) is a number: the substeps are set from it once at the start, so a Continuation of τ (or of Δt) is refused.

  • W: height of the well (barrier W/16). η: gain of the sensitivity. Takezawa et al. use W = 1/4 and η = 20 with g/‖g‖_L²; η = 10 with L2Norm() (|D| g/‖g‖_L²) is the same on their domain of measure 2.
  • T: the time of the evolution per iteration (one forward solve, one sensitivity), split into n = ⌈T / (cfl Δt_lim)⌉ substeps of Δt = T/n, with the bound of Gershgorin Δt_lim = 2 / maxᵢ(κ Σⱼ|Kᵢⱼ| / mᵢ) of the explicit diffusion, from the assembled K and lumped mass m once at the start (0.375 h²/κ on a uniform mesh of squares; it holds on any mesh). T is physical: the evolution per iteration does not depend on the mesh, and the number of substeps grows like (h₀/h)² (the pointwise reaction needs √(κ Δt) ≲ 0.7 h; more than 10⁶ substeps per iteration is refused). The method keeps Δt = :auto. An event after the setup gives T, n, Δt, Δt_lim and ξ in mean cell sizes h̄ = (|D|/cells)^(1/d).
  • cfl: the substep relative to Δt_lim; :auto is 4/3 with :implicit and 1/3 with :explicit (h²/(8κ), the step of Takezawa et al.).
  • scheme = :implicit (default): each substep diffuses implicitly, (m/Δt + κK) ψ = m φ/Δt with the operator factorised once (the one of the step), and then applies the semi-implicit pointwise reaction of Takezawa et al. (their Eqs. 44–45) to ψ, with λ inside the tilt term, by a root on vectors. scheme = :explicit: the explicit substeps of Takezawa et al. (ψ = φ − Δt κ m⁻¹ K φ, no linear system and no factorisation), the scheme of the preset :takezawa2010.
  • substeps = n (an integer): n substeps of the Δt of the method per iteration, and T is ignored; Δt = :auto of the method is then cfl Δt_lim and a number replaces it (with :explicit, Δt ≤ Δt_lim is checked). With substeps = nothing (default) a number Δt of the method is refused.
  • settle: with the substeps frozen on one sensitivity the interface overshoots and comes back, and a few per cent of the material changes phase at every iteration. settle = true (that is settle = (window = 10, tol = 1e-3)) goes to one substep (of the same Δt) per iteration once the constraints are met and the relative range of the objective over the last window iterations is below tol (an event says so); a continuation jump starts the substeps and the window again. The default stop is only checked from the iteration after the settling (or from the start when n = 1). settle = (window = w, tol = t) changes the window and the tolerance (either can be left out). settle = false keeps the substeps and does not hold the default stop (give stop and maxiter yourself).
  • The default stop with the well (default_stop): the constraints met, the material changed less than 1e-2 in each of the last 5 iterations and the relative range of the objective over the last 10 below 1e-3 (StopCriteria(material_tol = 1e-2, objective_range = 1e-3, combine = :all); 2e-3 without the well: the interface of the well keeps a cycle of a few per mille of the material per iteration), after the settling. solve!(…; stop) replaces it (and is not held until the settling).

Mesh: with κ and T fixed, the compliance of the cantilever 2 × 1 (κ = 1e-5, T = 25, seed :hex) is the same within about 3 % on 100 × 50, 200 × 100 and 400 × 200 (with 2, 5 and 20 substeps), but the topology depends on the seed and on the mesh (the double well does not nucleate holes, and the seed is resolved differently on each mesh). The bridge of Takezawa et al. (a point load) is not comparable across meshes: its compliance grows like log(1/h).

With the well, sensitivity is not mandatory (it is the exact derivative, :design; :physical is refused), normalize defaults to L2Norm() and ExactVolume(max_step = :auto) lowers the target 1 % of |D| per iteration (spread over the substeps). Not with an interface map (Ersatz(), Step()). Per iteration: one forward solve, one adjoint, n back-substitutions (:implicit; none with :explicit) and n roots on vectors, no factorisation.

HyperShape.Methods.ExactVolume — Type
ExactVolume(; max_step = :auto, tol = 1e-4, maxiter = 50, constraint = nothing)

How ReactionDiffusion treats the volume (its default): natively, with a scalar multiplier λ found at every step so that the clipped design z = clamp(φ* − λ φ̌, lb, ub) meets the constraint (φ* the design after the reaction–diffusion step, φ̌ = A⁻¹ m the response of the step to a uniform unit source). It takes the constraint built with Volume (g ≤ 0), wherever it is in the problem; with none or with several, solve! throws: name the one to take with constraint = :name (any inequality g ≤ 0 evaluated without a state, linear or not). The other constraints go to the augmented Lagrangian of the method.

  • max_step: how much the target may go down per iteration, as a fraction of the measure |D| of the design domain: the target of iteration k is max(V_obj, V_{k−1} − max_step |D|), met with equality while it goes down; at V_obj the constraint is g ≤ 0 with λ ≥ 0. :auto (default): 0.02 when the constraint reads the material through an interface map (Step(), Ersatz()), nothing otherwise (a density: the target from the first iteration). nothing: the target from the first iteration. A number in (0, 1].
  • tol: tolerance of the root as a fraction of |D|, like max_step (1e-4: the volume within 1e-4 |D| of its target), converted to the units of the scaled constraint with its scale; the loop converges only with the constraint met to it.
  • maxiter: evaluations of the constraint per step at most.

The root of G(λ) = g(clamp(φ* − λ φ̌)) − g_k (non-increasing in λ) starts from the previous λ, inside the bracket given by the bounds (all values at the upper or at the lower bound): a linear constraint (a density) by Newton on the clipped vector (only vectors, no solve; the algorithm of Cui et al. 2023); a nonlinear one with a derivative (Ersatz()) by Newton with the derivative of the constraint, guarded by the bracket; Step() by regula falsi (Illinois) on the volume computed by the material meter of the step (the same quadrature as the Volume, from the nodal values: exact, cheap and without allocations), until at most one quadrature point changes side inside the bracket; it ends on its feasible side (the volume of Step() is piecewise constant, and on coarse meshes the jump of one point can be larger than tol). Without the meter (a Volume over part of the domain, another constraint) the evaluations of Step() go through the constraint, until the trials differ by less than 1e-9. If the evaluations run out before a feasible trial is seen, the step takes the bound of the bracket where every value is at its lower bound. Each evaluation of a nonlinear constraint updates the maps and integrates (no state is solved, but the integral reserves memory: about 70 kB per evaluation and 130 kB per derivative with Ersatz(), independent of the mesh); a linear one costs vector operations only, without allocations.

HyperShape.Methods.FunctionalOracle — Type
FunctionalOracle

Oracle (see HyperShape.Optimizers.AbstractOracle) of an Optimization: objective and gradient! call the objective functional at the requested design; each constraint i is gᵢ = (Fᵢ − rᵢ)/sᵢ with the bounds of its Constraint: a linear one gives (a, V) computed once at the start (linear_constraint), a nonlinear one is evaluated at the requested design (constraint, constraint_gradient!; a design-only one solves no state); weighted_gradient! differentiates w₀ f + Σ wᵢ gᵢ in one reverse sweep; inner/riesz! use the metric of the method.

  • It is the only writer of the variables z; a design equal to the current one is not set again, so the value cache of the functional avoids repeated forward solves.
  • It keeps a copy of the design, value and derivative of its last gradient!: after a rejected step, the optimiser asks again at that design and gets them without solves.
  • A gradient that is not finite throws OptimizationFailure.

HyperShape.Methods.Grey — Type
Grey(θ::PhysicalFields, dΩ; field = nothing)

Monitor of the measure of grey of a physical density, M_nd = 4/|Ω| ∫ ρ (1 - ρ) dΩ (Sigmund 2007): 0 for a 0/1 design, 1 for a uniform 0.5. Pass it to solve!(…; monitors = (grey = Grey(θ, dΩ),)) to add it to the history, the table and the closing line; it is not a stopping criterion. field is mandatory when θ has several fields. Costs one integral per iteration (about 90 kB of memory, independent of the mesh).

HyperShape.Methods.L1Mean — Type
L1Mean(c = 1.0)

Normalisation of the sensitivity of ReactionDiffusion (its default): C = c |D| / Σᵢ |gᵢ|, with gᵢ the derivative of the objective with respect to the nodal value i (a dual vector) and |D| the measure of the design domain. The normalised sensitivity density C gᵢ / mᵢ (mᵢ the lumped mass) then has mean absolute value c over the domain, whatever the mesh. c scales the reaction against the diffusion τ.

HyperShape.Methods.L2Norm — Type
L2Norm()

Normalisation of the sensitivity of ReactionDiffusion: C = |D| / (Σᵢ gᵢ² / mᵢ)^½, the normalisation of Kim et al. (2020) with the measure |D| of the domain in place of |D|^½ (so that τ keeps the same meaning as with L1Mean).

HyperShape.Methods.LumpedMass — Type
LumpedMass(dΩ)

Diagonal metric m = ∫ v dΩ assembled on each design space: the cell volumes for a P0 design, the lumped mass (row sums of the mass matrix) for a P1 design. inner(x, y) = Σ mᵢ xᵢ yᵢ, riesz!(g, dF) = dF ./ m.

LumpedMass()

The same on the triangulation of each design space, with a quadrature of degree 2 (exact for designs of order up to 2): no measure to give, and it follows the design spaces if the mesh changes.

OptHistory

HyperShape.Methods.OptResult — Type
OptResult

Result of solve!: status (:converged, :maxiter or :stalled, the last when the optimiser found no acceptable step in the last continuation stage; in an earlier stage this ends the stage), reason (the criterion met: the name of its keyword in StopCriteria, :custom for a stop function, or nothing), iterations, objective (scaled, at the final design), z (the OptVariables of the problem, at the final design, with the fields and the forward state in sync with it: get_values(result.z)), history (OptHistory), time (seconds of the call), state (the state of the optimiser, for advanced use) and start_scaling (the factor t by which an infeasible starting design was scaled towards the lower bound, nothing if it was not) and multipliers (named tuple, one per constraint: the last multiplier reported by the optimiser for a native constraint, the final λ of the augmented Lagrangian, after its last update, for the others) and problem (the Optimization of the last stretch of the run: the problem given to solve!, or the last one built by a rebuild of the discretization). HyperShape.Methods.OptState — Type
OptState

The state of an optimisation by name, what a Checkpoint writes and resume reads (also kept in problem.state[] by solve!, so resume = problem.state[] continues without files): iteration, stage, stage_iterations, z (the last accepted design), blocks and frozen_cells (by block), continuation (names), scales (named tuple: objective and one per constraint), history (OptHistory), method and optimizer (names), memory (of the step, see memory; nothing after a failure or an exception: a run resumed from such a state starts the optimiser again from init and is not the uninterrupted one), handled (for each constraint, :native or :lagrangian), lagrangian (nothing, or the multipliers, penalties, penalty references and number of updates of the augmented Lagrangian, by name), linear_offsets (the offset V of each linear constraint, kept so that a resumed run uses the same bits), discretization (the name of the discretisation of the run) and events (its rebuilds so far). HyperShape.Methods.Optimization — Type
Optimization(; objective, constraints = (;))
Optimization(z; objective, constraints = (;))
Optimization(model; design_setup, physics_setup)

Optimisation problem: minimise the Functional objective over the variables z behind it (given or not; when given they are checked) subject to the bounds of z and the named constraints, for example constraints = (volume = Vol, tip = Constraint(Tip; max = 0.25)): a functional alone is F ≤ 0 (as Volume), a Constraint gives bounds max, min or equal in the units of the functional. The names go to the history (history.constraints.volume), the banner and the checkpoint. Constraints may read states.

The optimiser treats some constraints itself (OC and SiMPL: one inequality that solves no state, typically the volume; see handles); the others enter its objective through the augmented Lagrangian of the method (DensityMethod(…; lagrangian = AugmentedLagrangian(…)), used by default and shown in the banner).

A constraint built as linear (Volume over identity or filter maps, or a Functional(…; linear = true)) is checked to be linear when the optimisation starts, and costs nothing in the loop (its vector is computed once). A nonlinear one is linearised at every step by the optimiser, which then corrects it with evaluations of the true constraint (one filter solve each, no forward solve): see OC and SiMPL.

The third form builds the problem from two functions of the user (factories), so that solve! can build it again during the run (see discretization in solve!): design_setup(model) returns a named tuple with z (the OptVariables, on spaces of model) and x (the DesignFields built on z); physics_setup(model, x) returns a named tuple with objective and optionally constraints, monitors (as the keyword of solve!) and output (the driver of an OptPostProcessor built without one, (post, ctx) -> …). Both are called once here and again at each rebuild; every name they return is kept in problem.design and problem.physics (for example problem.physics.θ). What is continued or does not depend on the mesh (a TanhProjection of a Continuation, a Parameter, the optimiser) is created once, outside the factories, and used inside them; everything that depends on the mesh (spaces, measures, fields, states, functionals, monitors, output) is created inside. The factories may be called several times: they should have no other effects. A name close to one of the contract (monitor, constraint, outputs, post, driver, objectives, J) without the right one is an error. After a run with rebuilds the variable problem of the script is the first problem: the last one is result.problem (both share problem.state[]).

The problem owns the context ctx (OptContext) that reaches the solve functions of the user, and problem.state[], the last OptState captured by solve! (at the end of a run, after a failure or an interruption; a solve! that throws before its first iteration leaves the previous one): pass it as resume to continue without files.

source
HyperShape.Methods.OptimizationFailure — Type
OptimizationFailure(msg)

Thrown by solve! when the optimisation cannot continue: the forward problem does not converge at the current design (first iteration or right after a continuation jump), every attempt of a step was rejected, or a gradient is not finite (failed adjoint). z, the fields and the states are left at the last accepted design, and the checkpoint (if any) is written first. history holds the OptHistory up to the last accepted iteration and iterations its number (nothing and 0 when thrown outside the loop).

HyperShape.Methods.ReactionDiffusion — Type
ReactionDiffusion(; τ, sensitivity, Δt = :auto, normalize = L1Mean(), volume = ExactVolume(), mass = :lumped,
                  void_weight = 1e-3, ls = LUSolver(), solve = nothing, diffusion = nothing, degree = 2,
                  lagrangian = AugmentedLagrangian(), reaction = nothing)
ReactionDiffusion(; κ, reaction = DoubleWell(), kwargs...)
ReactionDiffusion(preset::Symbol; τ, sensitivity, kwargs...)

Reaction–diffusion method (Yamada et al. 2010, Choi et al. 2011, Otomori et al. 2015, Kim et al. 2020): the design field φ (one nodal P1 field, φ ∈ [lb, ub]) evolves by an implicit step of

∂φ/∂t = −C g − λ + τ ℓ² Δφ,

that is (mass/Δt + τ ℓ² K) δ = −τ ℓ² K z − C g (K the diffusion matrix, ℓ² = |D|^(2/d) with |D| the measure of the design domain, so τ is dimensionless), φ* = z + δ, and then z = clamp(φ* − λ φ̌, lb, ub) with the multiplier λ of the volume found exactly at every step (ExactVolume). g is the derivative of the objective (plus the terms of the augmented Lagrangian of the other constraints) and C its normalisation (normalize).

The material is read through the maps of the user: a level set (bounds = (-1.0, 1.0), solid start init = 1.0) through an interface map, χ = :φ => Ersatz() or Step(); or a density (bounds = (0.0, 1.0)) through Identity() and a SIMP interpolation in the weak forms. Frozen zones of the design space (FieldVariable(…; frozen)) are not variables: the step leaves them as they are.

Mandatory (modelling decisions):

  • τ: diffusion coefficient (dimensionless; a number or a Parameter, which a Continuation can change, not with DoubleWell); larger values give simpler designs with thicker members. Or κ = τ ℓ² instead (exactly one of the two): the same diffusion as a physical length squared, τ = κ/ℓ² with ℓ² = |D|^(2/d) computed on the mesh (the banner shows both). The operator takes κ as given; with τ it takes τ ℓ², so τ = κ/ℓ² with that ℓ² gives the run of κ bit for bit, while τ = κ/2 on a domain of measure 2 can differ in the last bits (the measure is a sum of quadratures, not exactly 2).
  • sensitivity (not with reaction = DoubleWell(…), where it is :design): :physical takes the derivative with respect to the material, the interface map taken as the identity weighted by the material, (w₀ + (1 − w₀) χ) ∂j/∂χ (w₀ = void_weight): it nucleates holes, and the exact derivative through the map would refill the void (its value there is large: weak material, large strains); :design the exact derivative with respect to φ, for a density (without an interface map in the chain both are the same) and with the double well, where it is the default. :design with an interface map (Ersatz(), Step()) is not a method: the exact derivative lives on the cut cells and nothing holds the plateaus (solve! throws). The variant that only moves the boundary, from a start with holes (hole_seed), is a density with reaction = DoubleWell(…) (then sensitivity is not mandatory). hole_seed also gives perforated starts for :physical (studies of the dependence on the start). check_consistency always checks the exact derivative; with Ersatz() give it steps smaller than the default (h0 = 1e-3): larger ones cross the kinks of the cell fractions (a node changing sign) and the observed rates fall below 2 for a correct derivative.

Optional (each one replaceable, shown in the banner):

  • Δt: pseudo-time step (number or Parameter); :auto (default) is 0.2 when the problem reads the design through an interface map and 0.4 otherwise (shown in the banner). With a smaller Δt the topology depends on the path: the design passes through metastable plateaus and the diffusion keeps merging holes long after it looks converged; halved by RejectStep when the forward problem does not converge at the new design, back to its value at the next step.
  • normalize: L1Mean(c) (default c = 1), L2Norm(), MaxAbs(), or a function (g, m, area) -> C (g the derivative, m the lumped mass, area = |D|).
  • volume: ExactVolume(; max_step, tol, maxiter, constraint), or nothing (every constraint to the augmented Lagrangian; needs lagrangian = AugmentedLagrangian(…; native = ())).
  • mass: :lumped (default; the response φ̌ is positive and G(λ) monotone on non-obtuse meshes) or :consistent.
  • void_weight: w₀ of sensitivity = :physical, default 1e-3.
  • ls: the linear solver of the step (a Gridap LinearSolver), default LUSolver(): the operator is assembled once by HyperShape (Gridap's assembler, on the design space), factorised once and again only when Δt or τ change. solve = (A, b, x, ctx, stale) -> x replaces it (PETSc, an iterative solver of the user): A the operator, b the right-hand side, x the output, stale whether A changed since the last call.
  • diffusion = (φ, v) -> ∫(…)dΩ: the bilinear form of the diffusion (default ∫(∇(φ) ⋅ ∇(v))dΩ with a quadrature of degree degree), for an anisotropic diffusion or a Robin term.
  • lagrangian: the AugmentedLagrangian of the constraints the step does not treat (everything but the volume).
  • reaction: nothing (default: the linear reaction −C g − λ above) or DoubleWell(…), the double-well reaction of Takezawa et al. (2010) for a density that only moves its interface, from a start with holes: then sensitivity defaults to :design, normalize to L2Norm(), Δt = :auto is T/n per substep (the time T of the well per iteration in n substeps) and the multiplier of ExactVolume acts inside the tilt term of the well (its max_step = :auto is 0.01). See its docstring for the scheme, the substeps and the settling.

Presets (ReactionDiffusion(:kim2020; τ, sensitivity)): the keywords given replace those of the preset (the banner says which). :kim2020 (Kim et al. 2020, density): Δt = 0.1, normalize = L2Norm(), mass = :consistent, volume = nothing, lagrangian = AugmentedLagrangian(Bertsekas(μ0 = 0.2, growth = 1.025, window = 1, progress = Inf, μmax = 2.0); native = ()); τ is still mandatory (5e-4 for their cantilever, 1e-3 for their half MBB beam). The script sets the rest: a density φ₀ = 0.5 with bounds = (0.0, 1.0), SIMP p = 3, Volume(…; scale = |Ω|). :takezawa2010 (Takezawa, Nishiwaki and Kitamura 2010, the double well): reaction = DoubleWell(W = 0.25, η = 20, scheme = :explicit, substeps = 20, settle = false), the normalisation 1/‖g‖_L² (without |D|) and volume = ExactVolume(max_step = 0.01); the script sets κ (their κ = 1e-5 on the bridge 2 × 1, that is τ = 5e-6), the start with holes, k = max(φ³, 1e-5) and 100 iterations (stop = nothing). Differences with the paper: the multiplier of the volume is exact (instead of their rule for ζ) and the discretisation is P1 finite elements with lumped mass (instead of finite differences).

Per iteration: one forward solve, one adjoint (none with SelfAdjoint()), one assembly of the sensitivity, one product K z and one solve of the step (no factorisation); the volume costs a few evaluations of the constraint per step (vectors only for a density; the map and an integral each with an interface map, plus one derivative per Newton iteration with Ersatz(); the summary of solve! counts them). The default stop (default_stop) needs the constraints met, the change of the material ∫|χ_k − χ_{k−1}| / ∫χ_k below 2e-3 (1e-2 with DoubleWell) in each of the last 5 iterations and the relative range of the objective below 1e-3 over the last 10, the windows counted with the constraints met; StopCriteria(rate_tol), change_tol and phase_tol are options. √(τ|D|) is the length of the diffusion (a perimeter energy), not a minimum thickness: bars of one or two cells can remain. Neither the interface map nor the stopping criterion is a recommendation: the choice will be validated with more cases. The starting design is not made feasible (the volume goes down from a solid start, max_step of |D| per iteration). Checkpoints save the multiplier and the windows of the stop (a resumed run is the uninterrupted one, also with a larger maxiter). gtol and the resolved Δt live in the method: one method object serves one solve! at a time (not concurrent runs).

HyperShape.Methods.RebuildCheck — Type
HyperShape.Methods.RebuildCheck(; at = nothing, every = nothing, what = :design)

Builds the problem again on the same mesh, calling the factories of Optimization(model; design_setup, physics_setup) after the accepted iterations at (an integer or a collection) or every every iterations: both factories (what = :design) or only physics_setup, with the same design (what = :physics). The run continues from the state captured at that iteration (the path of resume), so with linear states solved by direct solvers it is the run of FixedMesh() bit for bit (the counts of solves aside: one forward solve and one filter more per rebuild, in the summary). A run resumed from a checkpoint written at an iteration of a rebuild does not rebuild there again. It checks that the factories capture nothing of the problem they replace, before paying for a change of mesh: at each rebuild the objective at the rebuilt problem is compared with the one of the history (identical, or its relative difference, on screen). A nonlinear state or an iterative solver starts from another initial guess after a rebuild, and agrees only to its tolerance.

HyperShape.Methods.RejectStep — Type
RejectStep(; shrink = 0.5, max_attempts = 5)

What to do when the forward problem does not converge at the design proposed by the optimiser: go back to the previous design, call shrink! on the optimiser with shrink (0 < shrink < 1: OC multiplies its move limit) and try again, at most max_attempts attempts per iteration; then throw OptimizationFailure. RejectStep() is the default of solve! (with the defaults, the step can go down to 1/16 of the first one).

Optimisers that evaluate their trials (SiMPL) handle failures inside their line search, so for them this only applies if a step is accepted at a design that cannot be evaluated again.

HyperShape.Methods.StopCriteria — Type
StopCriteria(; objective_range = nothing, window = 10, kkt_tol = nothing, kkt_rtol = nothing,
             stationarity_tol = nothing, stationarity_rtol = nothing, change_tol = nothing, rate_tol = nothing,
             phase_tol = nothing, phase_window = 5, material_tol = nothing, material_window = 5, combine = :any,
             grey_tol = nothing)

Convergence criteria; each one is off unless given, and the first one met stops the optimisation (the reason in OptResult is the name of the keyword). With a Continuation they only act in the last stage, unless it was built with close_early = true (then a criterion met in an earlier stage ends that stage).

  • objective_range: range of the objective over the last window iterations of the current stage, (max - min), relative to max(largest |f| in the window, 1e-3 |f₁|) (f₁ the objective of the first iteration of the run, so an objective that tends to zero still converges), below this value. A range, not the difference between the ends of the window, so an oscillation does not pass for convergence.
  • kkt_tol: optimality measure of the optimiser below this value (absolute: units of the scaled objective). kkt_rtol: the same, relative to the one of the first iteration of the run (off if that one is not a positive number). Only with optimisers that compute it (SiMPL; with OC solve! throws before the first iteration).
  • stationarity_tol: the stationarity measure of the paper of SiMPL, S = ‖z − P(z − g)‖_M (stationarity!, computed by OC and SiMPL at the design before the step, so the run stops one iteration after it is met), below this value (absolute: it depends on scale and on the metric; with Euclidean() it depends on the mesh, use LumpedMass()). stationarity_rtol: relative to the first finite value of the run. With a nonlinear constraint the projection uses the constraint linearised at z. OC computes it with the metric of DensityMethod (its step does not use it): give LumpedMass() for a value independent of the mesh, comparable with SiMPL.
  • change_tol: maximum(abs, Δz) of the step below this value. With a tanh projection it is rarely reached.
  • rate_tol: the rate of change, maximum(abs, Δz) divided by the step of the step (the pseudo-time step Δt of ReactionDiffusion, the one of the accepted step), below this value: a step shrunk after a rejection does not meet it by being short (measured: the iteration at which it stops still depends on Δt).
  • phase_tol: the fraction of the design domain that changes phase in an iteration below this value in each of the last phase_window iterations (default 5) of the run: the lumped mass of the nodes where the level set changes sign, over |D| (phase_change of the method). Only for a method whose design goes through an interface map (ReactionDiffusion with Step() or Ersatz()); solve! throws otherwise. The windows of phase_tol and material_tol are saved in the checkpoint: a resumed run stops where the uninterrupted one does.
  • material_tol: the material changed in an iteration, M_k = ∫|χ_k − χ_{k−1}| dΩ / ∫χ_k dΩ (material_change of the method: χ is the physical field read by the Volume constraint, cell by cell), below this value in each of the last material_window iterations (default 5) with the constraints met (the window starts again whenever a constraint is violated: it does not count the descent of the volume). For ReactionDiffusion (the step computes M_k from the nodal values, without solves or allocations, when the Volume integrates over the design domain through Identity(), Step() or Ersatz()); given without such a meter solve! throws, while the default stop of ReactionDiffusion drops it (an event and a line of the banner say so). A run that ends at maxiter with the material still changing says so.
  • grey_tol: the measure of grey of the design below this value, M_nd = Σᵢ mᵢ 4φ̂ᵢ(1 − φ̂ᵢ) / |D| (φ̂ the design scaled to [0, 1] by its bounds, mᵢ the lumped mass of the free values; nodal, without allocations; Kim et al. 2020). For ReactionDiffusion (grey_measure of the method); with other methods solve! throws before the first iteration (for a physical density use the monitor Grey).
  • combine: :any (default) stops when the first criterion given is met; :all when all of them are met in the same iteration, and then the window of objective_range also counts only iterations with the constraints met (the reason is :all). The default of ReactionDiffusion is StopCriteria(material_tol = 2e-3, objective_range = 1e-3, combine = :all).

The tolerances are not checked at the first iteration of a stage (after a continuation jump the first step restores feasibility and its measures say little); objective_range needs window iterations of the stage.

Gridap.Algebra.solve! — Method
solve!(problem::Optimization, method::AbstractMethod; maxiter, on_failure = RejectStep(),
       stop = default_stop(optimizer), continuation = nothing, checkpoint = nothing, post = nothing,
       monitors = (;), resume = nothing, discretization = FixedMesh(), verbose = 2, io = stdout) -> OptResult

Runs the optimisation from the current values of z. Mandatory: maxiter (total iterations, resumed ones included). Optional: on_failure (RejectStep, default RejectStep(shrink = 0.5, max_attempts = 5)), stop (StopCriteria; default default_stop: range of the objective below 0.1 % over 10 iterations of the last stage, or for ReactionDiffusion the material and the objective steady with the constraints met; stop = nothing runs maxiter iterations; or a function (or callable object) (info, history, ctx) -> Bool of the user, checked after every accepted iteration, with the StepInfo of the step (info.f is the objective before it), the OptHistory up to this iteration (a copy) and the context: true stops with reason :custom, under the same rules as StopCriteria (only in the last stage of a Continuation unless close_early; with a nonlinear constraint, only when it holds to the tolerance of the optimiser)), continuation (Continuation), checkpoint (Checkpoint), post (an OptPostProcessor: its driver is called at the starting design, at the accepted iterations that are multiples of every, at the end and after a failure, with the fields and the forward state at the accepted design) and monitors (a named tuple of monitors, such as (grey = Grey(θ, dΩ),): their values, see monitor_value, go to the history, the table and the closing line), resume (the folder of a Checkpoint, the result of load_checkpoint or problem.state[], an OptState), verbose and io. An OC whose move is continued by continuation gets its own move back when solve! returns or throws; the other continued parameters keep the values of the last stage.

discretization (FixedMesh() by default: the problem is not built again) says when the problem is built again during the run, which needs a problem built with Optimization(model; design_setup, physics_setup): HyperShape.Methods.RebuildCheck calls its factories again on the same mesh (a check of the factories before a change of mesh). The run continues from the state captured at the rebuild (as a resume), with the same history, checkpoint and post-processor; the result carries the last problem (result.problem). With factories, monitors and the driver of the post-processor come from physics_setup (monitors, output; the post-processor is then built without a driver, OptPostProcessor(; every, filepath)); with a discretisation that rebuilds, they cannot be given here, nor a metric fixed on the mesh (LumpedMass(dΩ); use LumpedMass()).

Screen output (verbose, default 2, printed to io): 0 nothing; 1 a banner (variables, constraint, metric, continuation, stopping criteria and failure handling, each marked when it is a default), the events (continuation jumps, rejected steps, stalls, a scaled start), a closing ✓/⚠/✗ line and a summary of solves and time; 2 also a row per iteration: objective, its relative change, constraint (red above 1e-3), optimality measure kkt, stationarity measure S, change of z, step, multiplier, continued parameters, monitors, forward, adjoint and filter solves, and time. true is 2, false is 0. The summary counts every solve of the call (those of rejected or stalled trials, the setup and the final synchronisation included).

With a checkpoint, an exception that is not an OptimizationFailure (an error in a solve, post or monitor function of the user, an interruption) writes a checkpoint at the last accepted design (history included) and is then rethrown; an OptimizationFailure writes its own.

If the starting design (not a resumed one) violates the constraint, it is scaled towards the lower bound, z = lb + t (z − lb) on the entries the constraint acts on (a linear constraint: so that it holds with equality; a nonlinear one: with t found by regula falsi so that -1e-6 ≤ g ≤ 0); t is returned in result.start_scaling and reported as an event when verbose ≥ 1. At a continuation jump the design is not touched: an optimiser that finds it infeasible restores feasibility in its next step.

Each iteration: the optimiser takes a step from the current design; the loop evaluates the new design (no solve when the optimiser already did, as SiMPL); if the forward problem does not converge there, the design is restored, the step shrunk and tried again. Solves per iteration: OC one filter, one forward, one adjoint (none for a self-adjoint functional) and one transposed filter; SiMPL one filter and one forward per trial of its line search (usually one), one adjoint and one transposed filter; one more forward after each continuation jump. A linear constraint costs nothing in the loop (its vector is computed once at the start); a nonlinear one costs, per step, one transposed filter for its derivative and one filter per correction (see OC and SiMPL), and no forward solve. With a nonlinear constraint the run only converges when the constraint also holds to the constraint_tol of the optimiser.

With several constraints, or one the optimiser does not treat itself, the method's augmented Lagrangian (DensityMethod(…; lagrangian)) takes the others: the banner says who treats each one, the table shows the largest violation and the largest |λ|, the multipliers are updated after every accepted iteration (no solve: the values at the accepted design are cached) and the run converges only when every constraint holds to its tolerance (a run that ends otherwise says which constraints do not). The scaled start acts on the native constraint only. A stop function receives the StepInfo of the optimiser, whose f is then the augmented objective; the history keeps the objective of the problem. Per iteration, the constraints of the augmented Lagrangian add no forward solve and, with their states, one adjoint solve per state in the same reverse sweep as the objective.
