HyperShape.Optimizers — Module
HyperShape.Optimizers

Optimisers for problems with a box-bounded design vector z and one linear (volume) constraint.

The module is independent of finite elements: an optimiser sees vectors, bounds and an oracle (see AbstractOracle). A new optimiser is a subtype of Optimizer that implements the four functions of the contract:

state = init(opt, z, oracle)            # memory and history
info  = step!(opt, state, z, oracle, ctx) # overwrites z with the next design, returns a StepInfo
reset!(opt, state)                      # forget the history (continuation jump, remeshing)
shrink!(opt, state, factor)             # roll back the last step and reduce the next one
source
HyperShape.Optimizers.AbstractOracle — Type
AbstractOracle

What an optimiser may ask about the problem. Methods to implement for a subtype O:

  • objective(o::O, z): value of the objective at z (forward problem only). Return NaN or Inf if the value cannot be computed (for example, the forward problem did not converge); the optimisers treat it as a failed trial.
  • gradient!(dF, o::O, z): writes the derivative ∂F/∂z (a dual vector, no metric applied) into dF. The optimisers only call it for the z of their last call to objective on this oracle, so an implementation can reuse the forward state of that call and only pay for the adjoint.
  • bounds(o::O): (lb, ub), the bounds of z (scalars or vectors of the length of z), with lb < ub.
  • linear_constraint(o::O): (a, V) for the constraint aᵀz ≤ V (a ≥ 0 is a dual vector, for example the derivative of the volume), or nothing if there is none.

Methods with a default (Euclidean metric); they are not exported, extend them as Optimizers.inner:

  • inner(o::O, x, y): inner product of two primal vectors; default dot(x, y).
  • riesz!(g, o::O, dF): primal representative g = M⁻¹ dF of a dual vector; default copyto!(g, dF).

Optimisers only use these functions, broadcasting and global reductions (dot, maximum) on the vectors. If the bounds, the constraint or the objective change (continuation), call reset! on the optimiser.

HyperShape.Optimizers.FunctionOracle — Type
FunctionOracle(f, df!; lb = 0.0, ub = 1.0, constraint = nothing, metric = nothing)

Oracle built from plain functions, for analytical tests and small problems.

  • f(z): objective value.
  • df!(dF, z): writes ∂F/∂z into dF.
  • constraint = (a, V): linear constraint aᵀz ≤ V.
  • metric = m: diagonal metric, inner(x, y) = Σ mᵢ xᵢ yᵢ and riesz!(g, dF) = dF ./ m (cell volumes for P0 designs, lumped mass for P1 designs). nothing is the Euclidean metric.

evaluations(o) returns (value, derivative), the number of calls of each kind.

HyperShape.Optimizers.OC — Type
OC(; move = 0.2, damping = 0.5, bisection_tol = 1e-3, max_bisections = 200)

Optimality criteria update of Andreassen et al. (top88, 2011) for one linear constraint aᵀz ≤ V:

zᵢ ← clamp(zᵢ Bᵢ^damping, max(lbᵢ, zᵢ - m), min(ubᵢ, zᵢ + m)),   Bᵢ = max(0, -∂F/∂zᵢ) / (λ aᵢ),

with m = move * (ub - lb) and λ > 0 found by bisection on aᵀz = V, starting from [0, 1e9]. The bisection stops when (λ₂ - λ₁)/(λ₁ + λ₂) ≤ bisection_tol and, as in top88, keeps the design of the last midpoint, so the constraint holds up to the bisection tolerance. With the defaults, the step is the one of top88.

Requires a linear constraint with a > 0. The objective is evaluated once per step and the new design is not evaluated (f_new = NaN, kkt = NaN). If the move limit does not allow reaching aᵀz ≤ V (infeasible start), the step is still taken and violation > 0 in the StepInfo.

HyperShape.Optimizers.SiMPL — Type
SiMPL(; linesearch = :armijo, c1 = 1e-4, max_backtracks = 30, max_growth = 10.0, root_tol = 1e-12,
        max_root_iterations = 100)

Sigmoidal mirror descent with a projected latent variable (Keith, Kim, Lazarov and Surowiec, arXiv:2409.19341; Kim, Lazarov, Surowiec and Keith, arXiv:2411.19421).

The design is written as z = lb + (ub - lb) σ(ψ) with the sigmoid σ(x) = 1/(1 + e⁻ˣ), so every iterate satisfies the bounds strictly. One step, with g = M⁻¹ ∂F/∂z (see riesz!):

ψ ← ψ - α (g + μ M⁻¹a),

where μ ≥ 0 is zero if the constraint aᵀz ≤ V is inactive and otherwise solves aᵀz(ψ) = V (Newton iteration kept inside a bracket).

Step size: α₀ = 1/maximum(abs, g) after init/reset!; afterwards √(α_GBB α_prev) with the generalised Barzilai–Borwein step α_GBB = (ψₖ - ψₖ₋₁, zₖ - zₖ₋₁)_M / |(gₖ - gₖ₋₁, zₖ - zₖ₋₁)_M|, capped at max_growth * α_prev (each rejected trial costs a forward solve). The step is halved until

  • linesearch = :armijo: F(z_new) ≤ F(z) + c1 ∂F/∂z ⋅ (z_new - z), or
  • linesearch = :bregman: F(z_new) ≤ F(z) + ∂F/∂z ⋅ (z_new - z) + D(z_new, z)/α, with D the Bregman divergence of the (scaled) Fermi–Dirac entropy in the metric M.

A trial with a non-finite objective counts as failed. If no step is accepted after max_backtracks halvings, z is left unchanged and accepted = false. The tests allow a decrease lost in rounding (10 eps |F|), so a converged design keeps returning accepted steps with a negligible change instead of a failed line search.

Cost per step: one call to gradient! and one call to objective per trial (the value at the accepted trial is reused as the value of the next step). After init, reset! or a change of z by the caller, one more objective.

Optimality measure (kkt in StepInfo): (1, η)_M with λ = (ψ_trial - ψ)/α at the first trial of the step and η = max(-(z - lb) λ, (ub - z) λ) (eq. 23a of arXiv:2411.19421).

Requires a ≥ 0 (not all zero) in the linear constraint.

HyperShape.Optimizers.StepInfo — Type
StepInfo

What step! reports about one design step.

  • accepted: false if no acceptable step was found; z is then left unchanged.
  • f: objective at the design before the step.
  • f_new: objective at the new design, if the optimiser evaluated it (NaN otherwise).
  • kkt: optimality measure at the design before the step, if the optimiser computes one (NaN otherwise).
  • change: maximum(abs, z_new - z_old).
  • step: step size (SiMPL) or move limit (OC) used.
  • violation: max(0, aᵀz - V) of the linear constraint at the returned design (0 without constraint).
  • evaluations: number of calls to objective in the step (forward solves).

HyperShape.Optimizers.shrink! — Function
shrink!(opt::Optimizer, state, factor)

Called by the loop after it rejected the last step and restored z to its value before that step. Rolls back the memory of the optimiser to the start of that step and multiplies the size of the next step (or the move limit) by factor (0 < factor < 1). Consecutive calls accumulate; the reduction is dropped once a step stands (the next step! is called without a shrink! in between) or after reset!.

HyperShape.Operators — Module
HyperShape.Operators

Operators over HyperFEM computational models.

  • LinearOperator: auxiliary linear solves (filter, reaction–diffusion step, velocity extension). The model carries the bilinear form only and HyperShape supplies the right-hand side.
  • StateOperator: forward and adjoint states. The model carries the user's full weak forms.

Both declare their dependencies explicitly (depends = ...): objects with a version counter.

AbstractOperator

HyperShape.Operators.LinearOperator — Type
LinearOperator(model; depends, solve)

Linear solve with a matrix built by a HyperFEM model (typically a StaticLinearModel with the bilinear form alone) and a right-hand side supplied by HyperShape.

  • model: the computational model; its matrix and solver are the user's.
  • depends: the objects the matrix depends on (one object or a tuple; each implements version); () if the matrix never changes. Mandatory.
  • solve: user function (model, b, ctx, stale) -> x that solves with the right-hand side b and returns the solution vector. stale is true when something in depends changed since the last solve, so the user can re-assemble, for example solve = (m, b, ctx, stale) -> solve!(m, b; Assembly = stale). Mandatory.

The matrix must be the one the model assembled at construction (no dependency has changed yet). The returned vector is copied, so it may be a buffer of the model.

source
HyperShape.Operators.StateOperator — Type
StateOperator(model; depends, solve)

Forward or adjoint state: a HyperFEM computational model built by the user (weak forms and solver are the user's) that is solved again only when one of its dependencies changed.

  • depends: the objects the state depends on (one object or a tuple), typically θ for a forward state and (θ, S) for its adjoint. Each implements version; physical fields and other state operators are brought up to date first. Mandatory.
  • solve: user function (model, ctx) -> result that solves the model, for example (m, ctx) -> solve!(m; stepping = …) or (m, ctx) -> solve!(m; Assembly = true). The result is either the solution vector (taken as converged) or a tuple whose last element is the convergence flag: a Bool, or 1/0 as the flagconv of (x, flagconv) returned by HyperFEM's nonlinear models. Mandatory.

get_state(S) is the state field of the model, created once, so the forms of other models (the adjoint) can capture it; it always holds the model's current solution vector.

Failures do not throw. When the solve does not converge, or a state this one depends on did not converge (then this one is not solved), apply! returns false, is_converged is false and the functionals that need the state return NaN. After a failure get_state(S) holds whatever the model left (for HyperFEM's nonlinear models, the last converged load increment), not a solution. A failed solve is not repeated until a dependency changes; the next solve starts from what the model holds, as decided by the user's solve (RestartState in HyperFEM).

HyperShape.Variables — Module
HyperShape.Variables

Design variables at three linked levels:

LevelObjectWhat it is
zOptVariableswhat the optimiser sees: one vector made of blocks, with bounds
xDesignFieldsdesign fields on the design mesh (cell-wise P0 or nodal P1)
θPhysicalFieldsphysical fields read by the weak forms at the quadrature points

Each level is built from the previous one, and only HyperShape writes them (in place). The maps x → θ (HelmholtzFilter, Heaviside, Identity) are composed with ∘ in the mathematical order: Heaviside(β = 1.0, η = 0.5) ∘ HelmholtzFilter(Sf; measure = dΩ) filters first and projects after.

Sensitivities travel backwards with design_gradient!: a linear form in δθ for each physical field gives the derivative with respect to z.

source

DesignFields(z::OptVariables; name = Identity(), ...)

HyperShape.Variables.FieldMap — Type
FieldMap

Supertype of the maps x → θ. Compose them with ∘ in the mathematical order: (g ∘ f)(x) = g(f(x)).

source
HyperShape.Variables.FieldVariable — Type
FieldVariable(V; bounds, init)

Block of OptVariables holding the free values of a scalar design field in the space V (cell-wise P0 or nodal P1 Lagrangian, without Dirichlet conditions; the bounds act on the free values, which bound the field only for these two spaces). bounds = (lb, ub) with lb < ub; init is a number or a vector of the length of the free values, inside the bounds. Both are mandatory.

source
HyperShape.Variables.Heaviside — Type
Heaviside(; β, η)

Smooth Heaviside projection (Wang, Lazarov and Sigmund, 2011), applied point by point at the quadrature points:

H(ρ) = (tanh(βη) + tanh(β(ρ - η))) / (tanh(βη) + tanh(β(1 - η)))

β > 0 (sharpness) and 0 < η < 1 (threshold) are mandatory. β can be changed during the optimisation with set_beta! (continuation); every field and form built from this object sees the new value, and the physical fields that use it count as changed.

source
HyperShape.Variables.HelmholtzFilter — Type
HelmholtzFilter(op::LinearOperator; measure)

PDE filter (Lazarov and Sigmund, 2011): the filtered field ρ̃ solves a(ρ̃, v) = ∫(x v) dΩ for all v, where a is the bilinear form of the model of op (for example a(ρ̃, v) = ∫(r^2 ∇(ρ̃)⋅∇(v) + ρ̃ v)dΩ, solver chosen by the user) and dΩ = measure. The output is a field of the trial space of that model (usually P1), also for a P0 design field. The bilinear form must be symmetric (the same solve gives the transpose for the sensitivities; this is not checked) and the trial space may only have homogeneous Dirichlet values (checked).

Cost: one assembly of a load vector and one solve each time the design changes, and the same for each sensitivity pulled back.

HyperShape.Variables.OptVariables — Type
OptVariables(; name = FieldVariable(...), ...)

What the optimiser sees: one vector z made of named blocks, with bounds. Read it with get_values(z) and get_bounds(z). After writing into get_values(z) in place, call changed!(z) so that the design and physical fields are updated; set_values!(z, v) does both.

source
HyperShape.Variables.PhysicalFields — Type
PhysicalFields(x::DesignFields; name = map, other = :source => map, ...)

Physical fields θ, the ones the weak forms read. Each one comes from one design field through a map (a FieldMap, possibly composed with ∘): ρ = map uses the design field ρ; E = :ρ => map uses the design field ρ under another name, so several physical fields can come from the same design field (their sensitivities are added). Every design field must be used. The constructor brings the fields up to date once, calling the solve functions of the operators with ctx = nothing. Read a field as θ.ρ: a fixed object (an FEFunction or a CellField) updated in place, so the weak forms can capture it.

HyperShape.Operators.version — Method
version(θ::PhysicalFields)

Counter of changes of the physical fields. It grows in update_fields! when z or a parameter of a map (set_beta!) changed. Note that the fields themselves read β lazily: forms assembled after set_beta! already see the new value, but operators that depend on θ only notice the change after update_fields!. Two PhysicalFields built on the same DesignFields are independent: each one is brought up to date by its own update_fields!.

HyperShape.Variables.design_gradient! — Method
design_gradient!(gz, θ::PhysicalFields, forms::NamedTuple, ctx) -> gz

Derivative with respect to z of a quantity whose derivative with respect to the physical fields is given as linear forms: forms = (ρ = δ -> ∫(… * δ)dΩ, …), one entry per physical field it depends on (missing fields contribute nothing). The forms are pulled back through the maps x → θ (transposed filters, derivatives of the projections), assembled on the design spaces, added over the physical fields that share a design field, and mapped to z. Writes gz (a vector of the length of z).

HyperShape.Functionals — Module
HyperShape.Functionals

Objectives and constraints. A Functional evaluates a quantity of interest and its derivative with respect to the optimisation variables z, from forms written by the user with respect to the physical fields θ.

source
HyperShape.Functionals.Functional — Type
Functional(Jform, DJform, S, A, θ; scale)
Functional(Jform, DJform, θ; scale)

Objective or constraint.

With states (first form):

  • Jform(u, θ): value, a DomainContribution (∫(…)dΩ) or a number; u = get_state(S).
  • DJform(u, p, θ): total derivative with respect to the physical fields, ∂J/∂θ − ∂R/∂θ contracted with the adjoint p = get_state(A): a function δ -> ∫(… * δ)dΩ when θ has one field, or a named tuple of such functions ((ρ = δ -> …, E = δ -> …)), one per physical field it depends on.
  • S: forward StateOperator; A: adjoint state operator, which solves a(w, p) = ∂J/∂u[w] for all w (with a the tangent of the forward problem) on a space with homogeneous Dirichlet values; S must depend on θ and A on θ and S. For a self-adjoint functional pass A = S (then p = u; valid only when the Dirichlet values of the state are zero) and include the sign in DJform. Non-zero Dirichlet values in the trial space of the adjoint are detected when the gradient is computed.

Design only (second form, volume, perimeter): Jform(θ) and DJform(θ).

scale is mandatory: a positive number, :initial (the absolute value of the first finite evaluation; an error if it is zero) or 1.0 for no scaling. The value and the derivative are divided by it.

The value is kept until θ or a state changes; the gradient is assembled at every call (one adjoint solve only when the design changed, one transposed filter solve per filter and one assembly per call).

If a state does not converge, functional_value returns NaN and functional_gradient! fills the gradient with NaN (the optimisers treat it as a failed trial).
