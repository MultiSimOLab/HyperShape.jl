Variables

HyperShape.Variables — Module
HyperShape.Variables

Design variables at three linked levels:

LevelObjectWhat it is
zOptVariableswhat the optimiser sees: one vector made of blocks, with bounds
xDesignFieldsdesign fields on the design mesh (cell-wise P0 or nodal P1)
θPhysicalFieldsphysical fields read by the weak forms at the quadrature points

Each level is built from the previous one, and only HyperShape writes them (in place). The maps x → θ (HelmholtzFilter, TanhProjection, Identity) are composed with ∘ in the mathematical order: TanhProjection(β = 1.0, η = 0.5) ∘ HelmholtzFilter(dΩ; rmin, ls) filters first and projects after.

Sensitivities travel backwards with design_gradient!: a linear form in δθ for each physical field gives the derivative with respect to z.

The vectors HyperShape assembles (load vector of a filter, sensitivities) use backend = :compiled by default (HyperFEMKernels: forms compiled once into threaded kernels) or backend = :lazy (Gridap's assembler); see HelmholtzFilter and PhysicalFields. Both give the same vectors up to rounding. The compiled backend is faster from tens of thousands of cells on, already with one thread, and scales with the threads (julia -t N); on meshes of about a thousand cells both take well under a millisecond per vector.

HyperShape.Variables.CellMean — Type
CellMean(dΩ; backend = :compiled)

Mean of the input field over each cell of the triangulation of dΩ: a P0 field, x̄_K = ∫_K x dΩ / |K| (with the quadrature of dΩ). On a measure over part of the domain the field is the mean on those cells and its integrals over the whole domain only see that part (Gridap's rule for fields on a sub-triangulation). After a filter it gives the density of codes such as top88 (xPhys = TF'·K⁻¹·TF·x): one value per element instead of the filtered field at the quadrature points. Linear in its input (a volume after it stays a linear constraint); no solve. backend assembles its vectors (:compiled, HyperFEMKernels, or :lazy, Gridap).

θ = PhysicalFields(x; ρ = CellMean(dΩ) ∘ HelmholtzFilter(dΩ; rmin, ls = LUSolver()))

HyperShape.Variables.DesignFields — Type
DesignFields(z::OptVariables; name = Identity(), ...)

Design fields x built from the blocks of z, one per block and with the same name. Each map z → x is mandatory; only Identity is available for now. Read a field as x.ρ (a Gridap FEFunction, updated in place).

FieldMap

Supertype of the maps x → θ. Compose them with ∘ in the mathematical order: (g ∘ f)(x) = g(f(x)).

HyperShape.Variables.FieldVariable — Type
FieldVariable(V; bounds, init)

Block of OptVariables holding the free values of a scalar design field in the space V (cell-wise P0 or nodal P1 Lagrangian, without Dirichlet conditions; the bounds act on the free values, which bound the field only for these two spaces). bounds = (lb, ub) with lb < ub; init is a number or a vector of the length of the free values, inside the bounds. Both are mandatory.

HyperShape.Variables.HelmholtzFilter — Type
HelmholtzFilter(dΩ; rmin, order = 1, backend = :compiled, model_backend = <default>, solve = <default>, kwargs...)
HelmholtzFilter(op::LinearOperator, dΩ; backend = :compiled)

PDE filter (Lazarov and Sigmund, 2011): the filtered field ρ̃ solves a(ρ̃, v) = ∫(x v) dΩ for all v.

  • Short form (the usual filter): a(ρ̃, v) = ∫(r² ∇ρ̃⋅∇v + ρ̃ v)dΩ with r = rmin / (2√3), homogeneous Neumann conditions, on a Lagrangian space of degree order (continuous) over the triangulation of dΩ. kwargs go to HyperFEM's StaticLinearModel (for example ls = LUSolver(), ls = CGSolver(…) or a PETSc solver; without ls HyperFEM's default solver is used), model_backend is passed to it as its backend (who assembles the matrix; HyperFEM's default if omitted) and solve goes to the LinearOperator (default: assemble when the matrix changes).
  • General form: op is a LinearOperator whose model carries the bilinear form and the solver written by the user (Robin terms, Dirichlet conditions, anisotropy…). The bilinear form must be symmetric (the same solve gives the transpose for the sensitivities; checked by check_consistency) and the trial space may only have homogeneous Dirichlet values (checked).

The output is a field of the trial space of the filter (usually P1), also for a P0 design field. backend selects who assembles the load vectors of the filter: :compiled (default, HyperFEMKernels) or :lazy (Gridap); it is independent of the backend of the filter model, which assembles the matrix.

Cost: one assembly of a load vector and one solve each time the design changes, and the same for each sensitivity pulled back.

HyperShape.Variables.OptVariables — Type
OptVariables(; name = FieldVariable(...), ...)

What the optimiser sees: one vector z made of named blocks, with bounds. Read it with get_values(z) and get_bounds(z). After writing into get_values(z) in place, call changed!(z) so that the design and physical fields are updated; set_values!(z, v) does both.

HyperShape.Variables.PhysicalFields — Type
PhysicalFields(x::DesignFields; name = map, other = :source => map, ..., backend = :compiled)

Physical fields θ, the ones the weak forms read. Each one comes from one design field through a map (a FieldMap, possibly composed with ∘): ρ = map uses the design field ρ; E = :ρ => map uses the design field ρ under another name, so several physical fields can come from the same design field (their sensitivities are added). Every design field must be used. The constructor brings the fields up to date once, calling the solve functions of the operators with ctx = OptContext(:setup). Read a field as θ.ρ: a fixed object (an FEFunction or a CellField) updated in place, so the weak forms can capture it.

backend (a reserved name: no physical field can be called backend) selects who assembles the sensitivities on the design spaces: :compiled (default, HyperFEMKernels) or :lazy (Gridap).

HyperShape.Variables.PointwiseMap — Type
PointwiseMap(f, df; parameters = ())

Map applied point by point at the quadrature points, θ = f(input), with its derivative df written by the user (no automatic differentiation; check it with check_consistency): for example a projection or a threshold of the user's own. f and df are functions of one number. If they read Parameters (or other objects with a state_version), list them in parameters, so the physical fields count as changed when they change (continuation). Lazy, like TanhProjection: nothing is recomputed, the forms evaluate f and df when they are assembled.

const p = Parameter(8.0)       # const: closures that read it do not allocate
smooth_step = PointwiseMap(ρ -> 1 / (1 + exp(-p[] * (ρ - 0.5))),
                           ρ -> (s = 1 / (1 + exp(-p[] * (ρ - 0.5))); p[] * s * (1 - s)); parameters = (p,))
θ = PhysicalFields(x; ρ = smooth_step ∘ HelmholtzFilter(dΩ; rmin, ls))

HyperShape.Variables.TanhProjection — Type
TanhProjection(; β, η)

Smooth approximation of the Heaviside step (Wang, Lazarov and Sigmund, 2011), applied point by point at the quadrature points:

H(ρ) = (tanh(βη) + tanh(β(ρ - η))) / (tanh(βη) + tanh(β(1 - η)))

β > 0 (sharpness) and 0 < η < 1 (threshold) are mandatory. β can be changed during the optimisation with set_beta! (continuation); every field and form built from this object sees the new value, and the physical fields that use it count as changed.

HyperShape.Operators.state_version — Method
state_version(θ::PhysicalFields)

Counter of changes of the physical fields. It grows in update_fields! when z or a parameter of a map changed (set_beta!, a Parameter of a PointwiseMap or of a filter's operator). Note that the fields themselves read β lazily: forms assembled after set_beta! already see the new value, but operators that depend on θ only notice the change after update_fields!. Two PhysicalFields built on the same DesignFields are independent: each one is brought up to date by its own update_fields!.

HyperShape.Variables.add_forms! — Method
add_forms!(θ::PhysicalFields, forms::NamedTuple, w, ctx; key = 0) -> θ

Adds w times the derivative given by forms ((ρ = δ -> ∫(… * δ)dΩ, …), one entry per physical field; missing fields contribute nothing) to the reverse sweep started by reset_sink!. Projections and pointwise maps act inside the integrals now; filters only accumulate, and are solved once by finish_sink!. key identifies the forms for the compiled backend (see design_gradient!).

HyperShape.Variables.design_gradient! — Method
design_gradient!(gz, θ::PhysicalFields, forms::NamedTuple, ctx; key = 0) -> gz

Derivative with respect to z of a quantity whose derivative with respect to the physical fields is given as linear forms: forms = (ρ = δ -> ∫(… * δ)dΩ, …), one entry per physical field it depends on (missing fields contribute nothing). The forms are pulled back through the maps x → θ (transposed filters, derivatives of the projections), assembled on the design spaces, added over the physical fields that share a design field, and mapped to z. Writes gz (a vector of the length of z). It is reset_sink!, add_forms! with weight one and finish_sink!.

key identifies the quantity for the compiled backend, which keeps the compiled forms of the last keys used: with a different key for each quantity (objective, each constraint) the forms are only rebound at every call; forms of different structure under one key are correct too, their kernels are compiled again at each call (a few milliseconds). Avoid creating the Measure inside a form or capturing a new FEFunction at every call: both change the structure of the form.

HyperShape.Variables.finish_sink! — Method
finish_sink!(gz, θ::PhysicalFields, ctx) -> gz

Ends a reverse sweep: pulls the accumulated sensitivities back through the filters (one transposed solve per filter with something accumulated), adds them over the physical fields that share a design field, maps them to z and writes gz (a vector of the length of z).

HyperShape.Variables.single_field_design — Method
single_field_design(name, V; bounds, init, map, backend = :compiled) -> (z, x, θ)

Shortcut for one design field and its physical fields with the same name:

z, x, θ = single_field_design(:ρ, Vρ; bounds = (0.0, 1.0), init = 0.5,
                              map = TanhProjection(β = 1.0, η = 0.5) ∘ HelmholtzFilter(dΩ; rmin, ls))

is OptVariables(ρ = FieldVariable(Vρ; bounds, init)), DesignFields(z; ρ = Identity()) and PhysicalFields(x; ρ = map, backend): map is the chain from the design field to the physical one.
